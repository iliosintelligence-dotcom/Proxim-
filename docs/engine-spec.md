# Proxim engine specification (normative, spec version 1)

Status: M0/M1, 2026-10-11. Ports (Kotlin/Swift/TS) MUST match the golden vectors (section 9) byte for byte. This file wins over PLAN.md and the addenda on engine behaviour. [P] = provisional default: data in `proxim-types::defaults`, never hard-coded in logic. Sources: PLAN 5.5, 5.6, 6.1; ADDENDUM-01 2.2, 4.1; PLAYBOOK 4.

## 0. Scope

Crates `proxim-types`, `-geo`, `-path`, `-detect`, `-decide`: pure integer functions for foreground and partner-fed fixes (PLAN 5.3 M1/M2), hosted ads, one fix per call; no network, clock, randomness, file or OS access (I1, E3). Built in M1: `enter`, `approach`, internal exit hysteresis, path tiers P0/P1, consent fail-closed, per-signpost caps, minimal standoff, one-slot selection. Everything else is reserved (section 10).

## 1. Numeric model

### 1.1 Units (every field name carries its unit)

`Position {lat_e7, lon_e7}`: `i32` degrees x 1e7 (about 11 mm). `Enu {e_mm, n_mm}`: `i32` mm east/north of a frame origin. `_ms`: `i64` ms since Unix epoch UTC (`fix.t_ms` and `clock.now_ms` share one timeline). `_mmps`: `u32` (invalid speed = absent, never -1). `_ddeg`: `u16`, 0.1 degree clockwise from true north, 0..3599. `acc_mm`: 68% horizontal radius. `_permille`/`_milli`: 1000 = 1.0. Unit vectors: `[i32;2]` Q30 (east, north). Authored `_m`/`_s` fields are multiplied by 1000 at load. No engine type, input, output or golden file contains a float; shells convert with one binary64 multiply-add and floor (`lat_e7 = floor(deg*1e7 + 0.5)`). e7 is the wire form; geometry is evaluated in integer ENU mm (ADR-001); the trace is kept in e7 and re-projected per signpost frame.

### 1.2 Frame, projection, origin rule

`Frame {origin, kn_q32, ke_q32}`. The origin is never derived from the fix: it is the required `trigger.origin` (compiler rule: route anchor, circle centre, polygon bounding-box centre), so compiler and engines agree by construction.
- `lat_q = div_round(origin.lat_e7, 100000)` (0.01 degree grid; |lat| > 80 degrees -> `E_UNSUPPORTED_LATITUDE`).
- `(kn_q32, ke_q32) = SCALE[lat_q]`: mm per e7 unit in Q32, WGS84 at phi = lat_q x 0.01 degree: `kn = M(phi) pi/180 1e-4`, `ke = N(phi) cos(phi) pi/180 1e-4`, computed once per `lat_q` with `libm` in `proxim-geo::trig`, rounded. Normative table: `golden/trig/frame_scale_table.json`.
- `project(p)`: `dlon = wrap(p.lon - o.lon)` into [-1.8e9, 1.8e9) (`i64`); `e_mm = rsr(dlon*ke_q32, 32)`, `n_mm = rsr(dlat*kn_q32, 32)`, `rsr(x,s) = (x + 2^(s-1)) >> s` (arithmetic shift) in `i128`. `|e_mm|` or `|n_mm|` > 150_000_000 -> `E_OUT_OF_FRAME`.

Vertices are e7, projected at prepare time (memoizing is allowed). A fix farther than `trigger.reach_m` (optional; else geometry extent + `d_hi`/buffer + 100 m) from the origin is not a candidate.

### 1.3 Integer primitives

`div_round(a,b)` (b>0) = `floor((2a+b)/(2b))`; `isqrt(n:u128)` = exact floor sqrt; `dist = isqrt(dx^2+dy^2)`. Point-to-segment: clamp the dot-product parameter; perpendicular case `isqrt(cross^2 / len2)` (u128, floor). Within the 150 km frame every product is below 7.2e17 (`i64`) and every squared cross below 5.2e35 (`u128`). Arithmetic is checked: overflow -> `E_OVERFLOW`; no wrap, saturation, panic or unchecked indexing.

### 1.4 Accuracy and the straddle rule

`acc_eff = max(acc_mm, 10_000) x kappa_permille / 1000` (kappa 1000 [P]; inflation on Doppler residuals reserved). For signed depth `d` (inside positive) and factor `k`: `Inside` iff `1000 d >= k acc_eff`; `Outside` iff `1000 d <= -k acc_eff`; else `Straddle`. ENTER needs `Inside` (a fix whose accuracy circle straddles the boundary never counts; a straddle resets the candidate count); EXIT needs `Outside`. The one stated exception is corridor membership: it tests the centre point (`|xt| <= buffer`) because 65 m accuracy exceeds a 30 m buffer, compensated by 3 consecutive fixes, direction and closing gates and the 65 m cap (parallel roads within buffer + accuracy can fire, section 11).

## 2. Determinism and float confinement

1. Integer or fixed-point everywhere. Floats exist only in `proxim-geo::trig` and `::h3`, each with an explicit `#[allow(clippy::float_arithmetic)]`; elsewhere `float_arithmetic` and `float_cmp` are denied.
2. `trig` calls `libm` (sin, cos, sqrt) only on QUANTIZED finite domains and converts to integers at once: `SCALE[lat_q]` (16001 entries) and `SINCOS[course_ddeg]` (3600 entries, Q30, round-half-away; `cos(tol)` = `SINCOS[tol].cos`, tol <= 900). These are the only transcendental results in the engine; ports verify them exhaustively against golden digests or embed them. `atan2`, `exp`, `pow`, `ln`, `tan` are never used.
3. `h3` converts e7 to f64 degrees by one IEEE division for `h3o` 0.11.0 (current on crates.io 2026-10-11; `default-features = false` routes its trig through `libm`); only integer cell indices leave.
4. `core/clippy.toml` `disallowed-methods` lists std f64 `sin cos tan asin acos atan atan2 sinh cosh tanh exp exp2 exp_m1 ln ln_1p log log2 log10 powf powi cbrt hypot mul_add` (E1). The five crates are `#![no_std]` + `alloc`, so those methods, `HashMap`/`HashSet`, clocks, files and threads do not exist there (E2, E3); tests and tools may use `std`.
5. Signposts are processed and lists emitted in ascending byte order of `id` (ties `rev`); input order MUST NOT change output (`decide_ignores_input_order`).
6. Functions return `Result<_, EngineError>` (`E_PARSE E_OVERFLOW E_OUT_OF_FRAME E_UNSUPPORTED_LATITUDE E_DEGENERATE_GEOMETRY E_LIMIT`). A per-signpost defect is a drop reason, not an `Err`. A shell MUST treat any `Err` from `decide` as "no decision, state unchanged".

## 3. Crates, types, canonical JSON

### 3.1 Graph (deviation from PLAN 3, ADR-001)

`proxim-types` <- `proxim-geo` (+`h3o`, `libm`) <- `proxim-path` <- `proxim-detect` <- `proxim-decide`; `-pack`, `-events`, `-sched`, `-sim`, `-ffi`, `-wasm` depend on `proxim-types` (and decide), never the reverse. `proxim-types` holds wire types, `ReasonCode`, `EngineError`, `defaults` and the canonical writer. Limits: 4096 signposts, 1024 route / 256 polygon vertices, 256 standoff zones, trace 16, 4096 detector entries (excess -> `TRIGGER_INVALID` or `E_LIMIT`).

### 3.2 Canonical JSON (inputs, outputs, state, golden files)

UTF-8, no whitespace; keys ascending by UTF-8 bytes (via `serde_json::Value`, `BTreeMap`-backed: `preserve_order` is never enabled); integers only (no `+`, leading zeros, exponent or `-0`); no `null` (absent = omitted); array order is semantic; escape only `"`, `\` and controls < 0x20 as `\u00xx` lowercase; `Id` = ASCII `[A-Za-z0-9._:-]{1,64}`; enums lowercase snake_case, `ReasonCode` SCREAMING_SNAKE. Parsing is strict (unknown fields -> `E_PARSE`) except the reserved fields of section 10; any consent value other than exactly `"granted"` parses as `unknown` (I4).

### 3.3 Types (`?` optional, default in parentheses)

- `Fix {t_ms, lat_e7, lon_e7, acc_mm, speed_mmps?, speed_acc_mmps?, course_ddeg?, course_acc_ddeg?, is_mock?(false)}`. `Clock {now_ms, tz_offset_min:i16}`.
- `Consent {location_matching, nearby_health_events, aggregate_reporting, local_notifications: granted|denied|unknown (absent = unknown); health_receipt?}`.
- `Policy {simulator_mode?, child_directed?, explain?, categories_blocked?[], categories_accepted?[], category_affinity?[{category, weight_milli}], senders_blocked?[], sensitivity_ceiling?(2), lead_s_min?(15), lead_s_max?(120), cap_signpost_day?(2), cap_signpost_week?(5), app_min_interval_s?(1800), cap_sender_day?(3, lower only), cap_app_day?(4, lower or raise up to 8), slots?(1), max_acc_mm?(100000), standoff_zones?[{id, center, standoff_m(1000)}]}`. Partners only narrow: values clamp to platform ceilings (caps 2/5, slots 1, accuracy 100000, lead 15..120).
- `Signpost {id, rev, class: general|health, category, sender, sensitivity:u8, event, valid_from_ms, valid_until_ms, min_path_tier?(0; approach implies 1), min_path_conf_milli?(500), rank_milli?(1000), trigger}`; `EventKind = enter|approach|exit|cross|dwell|pass|sequence` (`exit` internal, not authorable).
- `Trigger {origin, reach_m?, shape, max_event_age_s?, max_event_dist_m?}` and, for `approach`, `{lead_s(40), d_lo_m?, d_hi_m?(3000, max 5000), mode: vehicle|cycle|foot, speed_min_mmps?, speed_max_mmps?, bearing_tol_ddeg?(300, 150..450)}`. `shape` = `{kind:circle, center, radius_m >= 150}` | `{kind:polygon, vertices[3..256] (no closing repeat), inradius_m?}` | `{kind:route, vertices[2..1024], buffer_m 30..500, anchor_along_m?(route length)}`. `enter` needs circle|polygon, `approach` needs route.
- `Decision {signpost, rev, outcome: fire|drop, reason, event, t_ms, path_tier, path_conf_milli, copy: near_you|ahead|on_route, d_rem_mm?, t_hat_ms?}`.
- `Output {v:1, t_ms, fix:{ok, reason}, path:{tier, conf_milli, speed_mmps?, heading_valid}, decisions[], notes?[{signpost, reason}]}`. No position ever appears in an Output (I2, I6). Without `policy.explain`, `decisions` holds only `fire` entries (at most `slots`), `notes` is absent, and a standoff reads `fix:{ok:false, reason:"SUPPRESSED"}`, so logging reasons cannot reveal proximity to a health facility. With `explain` (tests, simulator) drops and notes are listed.
- `State {v:1, caps, mem, controls?}`. Only `caps` and `controls` MAY be persisted (encrypted, no backup, I3); `mem` MUST NOT be persisted, logged or sent; a new process starts from `State::empty()` plus the persisted parts.
  - `caps {hwm_ms, last_fire_ms?, signposts[{id, day_idx, day_n, week_idx, week_n}] by id, senders?[{sender, day_idx, day_n, tz_offset_min}] by sender}`; signpost entries from earlier weeks and sender entries from earlier days are pruned each call.
  - `controls? {dismissed?[{id, until_ms}] by id, hidden?[id], reported?[sender]}` (7.2), sorted and unique, at most 256 / 1024 / 256 entries. Changed only by `controls::apply` (`apply_control_json`). Expired dismissals are pruned each call. An absent `senders` or `controls` is the engine_spec 1 form and reads unchanged.
  - `mem {last_t_ms?, jump_rejects, trace[{t_ms, lat_e7, lon_e7, acc_mm, v_mmps?}] (<=16, oldest first), vf_mmps?, h?[x,y] Q30, h_t_ms?, det[{id, rev, st}] by id}`. Idle detectors are absent; a changed `rev` replaces the entry; entries absent from the input and unseen for 900 s are pruned. `st` (tag `s`): `cand{n,first_t,last_t}` | `in{xn,x_first_t?,last_t}` | `cool{until_ms}` | `armed{confirm_t?,last_t}` | `latched{why: fired|late, last_t}`.

| Function | Semantics |

| `orient2d(a,b,c)->i8`, `dist_mm`, `dist_point_segment_mm` | exact cross-product sign; distances per 1.3 |

## 5. proxim-path

`path_update(mem, fix) -> (mem', PathSummary)`, accepted fixes only.

### 5.1 Speed filter (exact)

`v_meas`: `speed_mmps` if present and (`speed_acc_mmps` absent or <= 5000); else `dist x 1000 / dt_ms` (floor) to the newest trace entry aged 3000..10000 ms; else none. Rational EWMA, tau 8000 ms (no `exp`): `alpha_q16 = dt x 65536/(8000+dt)`, `dt = clamp(fix.t - last_t, 0, 60000)`; `vf' = vf + rsr((v_meas - vf) x alpha_q16, 16)`. Seed `vf' = v_meas` when `vf` is absent or `dt > 5000` (after a gap: the median of the last up to 3 `v_meas` values, `sorted[(n-1)/2]`). Without `v_meas`, `vf` is unchanged and hidden after 10 s. `v_eff = max(vf, floor)`, floors vehicle 4000, cycle 2000, foot 700.

### 5.2 Heading filter (exact)

Measurement `m`: the OS course vector if `course_ddeg` is present, its accuracy is absent or <= 450 and `vf >= 800`; else the unit displacement to the newest trace entry aged 3000..15000 ms if that is >= max(15000, 3 acc_eff) mm; else none. Tau 4000 ms: `a = dt x 65536/(4000+dt)`, `h' = normalize(rsr(h x (65536-a) + m x a, 16))`; reseed `h' = m` if `h` is absent, `dt > 5000` or the blend is zero. `heading_valid` iff updated within 10 s.

### 5.3 Tiers, confidence, copy ladder

- P0 presence: confident `Inside` (ENTER rule); conf 500; copy `near_you`.
- P1 corridor: `acc_eff <= 65000` on the last 3 fixes; >= 3 fixes within 60 s; `vf` >= mode minimum (vehicle 2500, cycle 1500, foot 500); heading valid and `dot(h, tangent) >= cos 45 deg`; `abs(xt) <= buffer` on the last 3 fixes; CLOSING. `conf = 600 +100 [>=5 fixes in 60 s pass] +100 [dot >= cos 15 deg] -100 [max acc_eff of last 3 > 30000] -200 [> 50000]`, foot capped at 600, or at 700 when the foot evidence is strong: both bonuses and the worst `acc_eff` of the last 3 fixes `<= 20000` (E-P-FOOT) (range 400..800); copy `ahead`.
- P2 route-confirmed (RESERVED): conf 800-900; copy `on_route`. P3 swath (RESERVED): conf <= 500, widener only.

CLOSING over the last three fixes (along a0,a1,a2; `tol = max(acc_eff)/2`): `a2-a0 >= max(5000, tol)`, `a1-a0 >= -tol`, `a2-a1 >= -tol`. U-turn, opposite carriageway and a stopped vehicle fail CLOSING or the heading gate. Health's floor 700 is reachable by P1 only with accuracy <= 30 m and a bonus (foot: only with strong foot evidence), never by P0.

### 5.4 Time to anchor

`d_rem = rem_along(anchor, along) - v_eff x age_ms / 1000` (dead reckoning, floor 0; `age_ms = now - fix.t` must be <= 10000 for approach else `FIX_STALE`). `t_hat_ms = d_rem x 1000 / v_eff` (floor; `v_eff >= 700`).

## 6. proxim-detect

`detect(st, sp, path, fix, now_ms, explain) -> (st', Option<Event>, Option<ReasonCode>)`; state is an explicit input and output. `Event {kind, t_ms, d_rem_mm?, t_hat_ms?, dist_to_shape_mm}`; the reason is a non-terminal "why not". Fire timing lives here because it defines when an event exists (ADR-001).

### 6.1 ENTER with EXIT hysteresis (circle, polygon)

`d` = signed depth in the shape's frame; `k_in = k_out = 1000` [P]. A shape whose inradius (circle radius; polygon `inradius_m` if given) is below `k_in x acc_eff` yields `ACC_TOO_COARSE`; circles need `acc_mm <= 50000`.
- Idle -> `cand{n=1}` on an `Inside` fix. In `cand`: `Inside` with gap <= 10000 ms increments `n`; anything else returns to idle (restarting at `n=1` if the new fix is `Inside`). ENTER fires at `n >= 3` and `last_t - first_t >= 3000` ms (10000 if `vf < 1500`) -> `in{xn=0}`.
- `in`: an `Outside` fix increments `xn` (the first sets `x_first_t`); any other fix zeroes it. Exit confirms at `xn >= 5` or (`xn >= 2` and `last_t - x_first_t >= 10000`) -> `cool{until = last_t + 1_800_000}`. EXIT is internal: no Event, nothing delivered or persisted. State survives gaps up to 120 s; a gap > 900 s becomes `cool{until = prev_last_t + 1_800_000}`. `cool` ignores fixes until `fix.t >= until`, then idle.

### 6.2 APPROACH (route)

`proj = project_to_polyline(route, fix, window)` in the trigger's frame; `window = [a_prev - 100 m, a_prev + 500 m + v_eff x 30 s]` once armed (blocks parallel-leg and loop confusion), else the whole route; `anchor = anchor_along_m x 1000`. Parameters: `lead_s` clamped by policy; `d_lo` (vehicle 150 m; foot/cycle `max(100 m, 3 acc_eff)`); `d_pass = max(60 m, 5 s x v_eff)`; `L_min = max(0.4 lead_s, 10 s)`; `t_comp = 3000 ms`; speed band from the trigger (vehicle >= 2500 mmps, free-flowing >= 8300, foot 500..2500) with 1000 mmps hysteresis once armed.

Gates, in order (first failure -> idle, reason noted): `FIX_STALE` (age > 10 s), `FIX_ACCURACY_TOO_COARSE` (`acc_eff > 65000`), `OFF_CORRIDOR` (`abs(xt) > buffer`, last 3 fixes), `SPEED_OUT_OF_BAND`, `BEARING_MISMATCH` (`dot(h, tangent) < cos(bearing_tol)`; invalid heading fails), `NOT_CLOSING`, `BEYOND_WINDOW` (`d_rem > d_hi` or `d_rem < d_pass`), `PATH_TIER_LOW`/`PATH_CONFIDENCE_LOW`.

idle -> `armed` on the first fix where all gates hold. At that fix, if `t_hat < L_min` and `d_rem > d_lo`: `latched{late}` and the terminal drop `TOO_LATE_FOR_LEAD` (late join). In `armed`: FIRE when `t_hat <= lead_s x 1000 + t_comp` or `d_rem <= d_lo` (crawl rule) has held on two accepted fixes >= 1000 ms apart (`confirm_t` = first confirming fix; a non-confirming armed fix or a gap > 5000 ms clears it). Equivalent: `D_fire = clamp(v_eff x (lead_s + 3 s), d_lo, d_hi)`. FIRE -> `latched{fired}`: one fire per pass. Re-arm (-> idle) only when the fix is farther than `1.2 x d_hi` (Euclidean) from the anchor point, or on a new `rev`; passing the anchor does not re-arm. A fix beyond `reach_m` returns armed to idle.

## 7. proxim-decide

`decide(state, fix, signposts, policy, consent, clock, seed) -> Result<(Output, State)>` is a function of its arguments only. `seed` is carried but UNUSED in M1 (a test asserts it).

`now = max(clock.now_ms, caps.hwm_ms)` (a clock set backwards cannot reopen caps), stored as `caps.hwm_ms`. `day_idx = floor_div(now + tz_offset_min x 60000, 86_400_000)`; `week_idx = floor_div(day_idx + 3, 7)` (Monday start). Hard filters in order, one reason code each:

Global (first failure ends the call):
- F01 `CONSENT_DENIED`: `location_matching != granted` -> `mem := empty`, nothing processed or retained (I4); `caps` kept. F02 `ENGINE_DISABLED`: `child_directed` -> `mem := empty` (I9).
- F03 `FIX_INVALID` (range), F04 `FIX_MOCK` (`is_mock`, not `simulator_mode`), F05 `FIX_ACCURACY_TOO_COARSE` (> `max_acc_mm`), F06 `FIX_FROM_FUTURE` (`t > now + 5000`), F07 `FIX_STALE` (`now - t > 30000`), F08 `FIX_OUT_OF_ORDER` (`t <= mem.last_t_ms`).
- F09 `FIX_JUMP`: against the newest trace fix with `dt <= 60000`: implied speed > 83000 mmps and distance > both accuracies + 100000 mm. Reject and count; the 3rd consecutive reject resets trace and detectors and accepts the fix.
- F10 `SENSITIVE_STANDOFF`: some `standoff_zones` entry with `dist(fix, center) <= standoff + acc_eff`. M1 minimal R1/R2: ALL classes are suppressed (stricter than R2's health-only text; relaxing is an M3 decision), `mem := empty` (no breadcrumb), `caps` untouched, call ends (I6).

Then `path_update`. Then per signpost in ascending `id`:
- Static (failure -> drop record, detector entry removed): F11 `UNSUPPORTED_EVENT` (E5); F12 `TRIGGER_INVALID` (shape/event mismatch, limits, radius < 150 m, buffer/lead/`d_hi` out of range, bad validity window, geometry outside the frame or degenerate); F13 `NOT_YET_LIVE`; F14 `EXPIRED`; F15 `HEALTH_CONSENT_MISSING` (`class=health` without `nearby_health_events=granted` and `health_receipt`, I12); F16 `PARTNER_CATEGORY_BLOCKED` (a blocked entry equals the category or is a whole-segment prefix of it), then `CATEGORY_NOT_ACCEPTED` (7.1); F17 `SENDER_BLOCKED`; F18 `SENSITIVITY_ABOVE_CEILING`; F19 `TRIGGER_IN_STANDOFF` (health geometry within a zone's standoff; defence in depth for R1).
- Detect (section 6) with the policy-narrowed trigger; quick reject (idle and beyond `reach_m`) records nothing. Gate reasons are non-terminal notes; `TOO_LATE_FOR_LEAD` is terminal.
- Event filters (a dropped Event is consumed, not retried): F20 `EVENT_TOO_OLD` (`now - event.t > max_event_age_s`; default enter 30 s, approach 10 s); F21 `EVENT_TOO_FAR` (`dist_to_shape > max_event_dist_m`, default 5000 m; zone: distance outside, route: cross-track); vacuous for a fresh foreground fix, they bind for late events (M3/M4) and are tested with an aged clock. F22 `CAP_SIGNPOST_DAY` (`day_n >= cap`, where a count stored under an older `day_idx` is 0: the bucket comparison happens before the cap check, never only in the commit step; E-D6, E-D-TZ), F23 `CAP_SIGNPOST_WEEK` (likewise with `week_idx`), F24 `CAP_APP_INTERVAL` (`now - last_fire_ms < app_min_interval_s x 1000`).
- Selection: survivors ordered by `(affinity_milli > 0 first (7.1), score desc, t_hat_ms asc, absent last, id asc)`, `score = rank_milli x path_conf_milli x affinity_milli / 1000000` (u64; `affinity_milli` 1000 unless 7.1 says otherwise, which is the M1 score exactly; `rank_milli` above 3000 counts as 3000, E-D-RANK). The first `slots` fire; the rest get F25 `LOST_SLOT` and revert to their pre-event detector state (they may fire at a later fix, subject to F24).
- Commit: winners get `day_n += 1`, `week_n += 1` (a new index resets the count), `last_fire_ms = now`, detector latched; nothing else is written. Decisions are sorted fire first, then `id`.

### 7.2 Sender and app day caps, user controls (engine_spec 2, M3)
- **User controls, static filters after F17, in this order:**
  - F17a `SENDER_REPORTED`: the signpost's sender is in `controls.reported`. Permanent on this device.
  - F17b `HIDDEN_BY_USER`: the id is in `controls.hidden`. Permanent for that signpost.
  - F17c `COOLDOWN_DISMISSED`: the id is in `controls.dismissed` and `now < until_ms`.
  - Dismiss sets `until_ms = now + 7 days`; dismissing again extends it, and a full list drops the entry that ends soonest. Like the other static filters, these drop the record and remove the detector entry.
  - The keys are the family (the signpost id) and the sender, never the wording, so rotation cannot bring a suppressed family back (Addendum 02 5.3).
- **Event filters:**
  - F23a `CAP_SENDER_DAY`, after F23: the sender's current-day count is at least `cap_sender_day` (default 3; a policy may only lower it).
  - F24a `CAP_APP_DAY`, after F24: the app's current-day count is at least `cap_app_day` (default 4; a policy may lower it, or raise it up to 8 for navigation and transit partners, PLAN 5.6).
  - The app's day count is the sum of every signpost entry's current-day count, so it needs no state of its own.
  - A sender entry is judged in the zone it was counted under, like the signpost entries (E-D-TZ).
- **Selection:** with more than one slot, an earlier winner in the same call can use up a sender's or the app's day. A later survivor is then consumed with `CAP_SENDER_DAY` or `CAP_APP_DAY` and takes no slot. With one slot (the M1 ceiling) this cannot happen.
- **Commit:** a winner also increments its sender's day count.

### 7.1 Category matching (added 2026-10-16)

Which adverts a partner app delivers is decided by the app's own policy, inside the app. No app sees another app, the engine never learns what else is installed, and matching uses no user data: only the partner's static policy and the signpost's `category`.
- Codes. A category is one to four dot-separated segments of `[a-z0-9_]` (1..=24 bytes each, 64 in all), most specific last: `health.hospital`, `food.cafe`. The shared list is `proxim_types::taxonomy::TAXONOMY` (industries and their sub-categories); the sender backend checks codes against it, the engine does not (an unknown code is matched like any string).
- Match. A pattern matches a category when it equals it or is a whole-segment prefix of it (`health` matches `health.hospital`, not `healthy.food`).
- `categories_blocked` (F16, unchanged position). Now also blocks every sub-category of a blocked entry. Entries are not syntax-checked (as before).
- `categories_accepted` (F16, after the block list). Empty: everything not blocked is accepted. Otherwise a category matching no entry is dropped with `CATEGORY_NOT_ACCEPTED` (id 210).
- `category_affinity`. The weight of the longest matching entry multiplies the selection score; 1000 is neutral and the default, values above 3000 clamp to 3000, 0 makes the category a last resort: in selection every candidate with a positive weight sorts before every candidate with weight 0, whatever the scores (so floor division of a small positive weight cannot tie it with 0). It reorders this app's candidates only: caps, slots and every filter are unchanged, so a weight never adds a delivery.
- Validation. Entries of `categories_accepted` and `category_affinity` must be well-formed codes and affinity codes must be unique, else `E_PARSE` for the call; more than 256 entries in either list is `E_LIMIT`.

## 9. Golden vectors

`core/testdata/golden/<kind>/<id>.json`, kinds `decide detect path geo h3 trig`; canonical JSON plus a trailing `\n`; synthetic data only (I2). Header: `{"format":"proxim-golden/1","kind","id","engine_spec":1,"synthetic":true}`.
- `decide`: `{header, seed, policy, consent, signposts[], steps[{clock, fix, expect:{output, state_sha256}}], trace_sha256}`. The runner starts at `State::empty()`, threads `state'` and compares the canonical bytes of `output` and the SHA-256 (lowercase hex) of the canonical bytes of `state'`; `trace_sha256` hashes `canon(output) + "\n" + state_sha256 + "\n"` over all steps.
- `geo path detect h3`: `{header, cases[{fn, args, result}]}` (integer args), including 1.3 rounding edges and every worked number here. `trig` tables: `{header, entries: every 100th row, sha256 of all rows as "idx,v1,v2\n"}`.
- Conformance entry (`proxim-ffi`, `proxim-wasm`): `decide_json(state, fix, signposts, policy, consent, clock, seed) -> {output, state}` in canonical JSON; CI `golden-vectors` needs identical bytes on every binding and OS.
- `MANIFEST.json` lists `{path, sha256}` per vector; regeneration needs `PROXIM_BLESS=1 proxim-sim golden --bless` and a reviewed diff; a byte change of a `decide` vector bumps `engine_spec`. A header's `engine_spec` records the spec the vector was made under: `decide` vectors must equal the current spec, other kinds stay valid until their own behaviour changes (E-SPEC2).

## 11. Behaviour contract, false positives and negatives

`proxim-sim-qa` measures these on the fixture routes.
- Radius 150 m, `acc_eff` 10 m: ENTER at <= 140 m, EXIT at >= 160 m; jitter around the edge never ENTERs.
- Time-to-anchor (steady, 1 Hz, `lead_s` 40, `d_lo` 150 m): `D_fire = clamp(v_eff x 43 s, 150 m, 3000 m)`: 29 m/s -> 1247 m (realized lead about 41 s), 15 m/s -> 645 m, cycle 5 m/s -> 215 m, jam 3 m/s (floor 4) -> 172 m.
- Must not fire: U-turn, opposite carriageway, unknown consent, inside a standoff (`caps` byte-identical, `mem` empty), a first armed fix with `t_hat < L_min` (e.g. after a 3 min GPS drop), a 3rd fire in a local day, a 6th in a week.
- False positives: a parallel same-direction road at distance `D` when `D < buffer + acc_eff` (tracked metric; P2 is the remedy). False negatives: stop-and-go below the 4 m/s floor fires at about 172 m, not earlier; heading is invalid below 800 mmps; urban-canyon correct-road accuracy is not promised (ADDENDUM-01 4.4); a spoofed GPX is indistinguishable (attestation is server-side, M9); `d_rem` follows the authored polyline, not the road.

### 2026-10-12, proxim-path and proxim-detect (path/detector implementer)

Conservative readings and clarifications; none changes a normative number. Measured behaviour is reproducible with `cargo test -p proxim-detect --test measure -- --ignored --nocapture`.
- E-P1 API shape. `path_update(mem, fix) -> (mem', PathSummary)` also pushes the trace (cap 16) and sets `last_t_ms`; a fix not strictly after `last_t_ms` is `E_PARSE` (decide maps it to F08 first). `PathSummary` adds `vf_mmps` (visible speed), `fixes_60s` and `recent[3]` (the newest three accepted fixes, the current one last) so `detect` needs no `Mem`; its `info` is the signpost-independent baseline (tier 0, conf 0). `Event` adds `path_tier` and `path_conf_milli` (0/500 for ENTER, 1/ladder for APPROACH); copy follows `copy_for_tier`. `Prepared::new(&Signpost)` validates and projects a trigger once (`Result<_, ReasonCode>`) and `Prepared::step` is the detector; `detect(...)` is the one-shot wrapper. `Detected.reason`: `TOO_LATE_FOR_LEAD`, `UNSUPPORTED_EVENT` and `TRIGGER_INVALID` are terminal and always reported; every other reason (gates, `NO_EVENT`, `FIX_OUT_OF_ORDER`, `ACC_TOO_COARSE`, `OUT_OF_RANGE`) is non-terminal and reported only with `explain`; state and event never depend on `explain`. `state == None` is idle (decide removes the entry).
- E-P2 Constants. The [P] numbers of sections 5 and 6 live as named constants in `proxim-path::params` and `proxim-detect::params` because `proxim-types::defaults` was closed for this stage. Moving them is a lead decision.
- E-P3 Speed filter (5.1). Heading's `vf >= 800` test uses the filtered speed after this fix's update. A `vf` not refreshed for 10 s is hidden and does not weigh into a new measurement (the new value reseeds). The "median of the last up to 3 v_meas values" after a gap above 5 s is taken over this measurement and the two newest earlier ones that are at most 10 s old (so after a gap above 10 s it is the measurement itself); with two values `sorted[(n-1)/2]` is the lower. "Hidden after 10 s" is derived from the trace (newest entry with `v_mmps`), so a trace shorter than 10 s of fixes (above 1.6 Hz) hides early (fail closed). Position-derived speed and heading use the local frame centred on the older trace entry and give no measurement above 80 degrees or beyond 150 km.
- E-P4 Heading filter (5.2). `dt` is the time since `h_t_ms`. Displacement heading uses only the newest entry aged 3..15 s and needs `max(15 m, 3 acc_eff)`: with acc_eff 10 m that is 30 m in 3 s, about 10 m/s, so pedestrians and most cyclists rely on the OS course (false negative, left as written). Because the blend is normalised each step, an exactly opposite measurement (weight below 0.5, i.e. `dt < 4 s`) cannot overturn the heading: after an abrupt 180 degree reversal the heading stays stale for roughly 15 fixes at 1 Hz. CLOSING (from positions) is what stops a fire in that window; the cost is a slow recovery after a real U-turn (safe direction).
- E-P5 CLOSING (5.3) needs exactly three fixes (fewer is `NOT_CLOSING`). It needs a net advance of `max(5 m, acc_eff/2)` over the last three fixes, so a walker at 1.4 m/s sampled at 1 Hz (2.8 m) never passes it. Foot P1 is reachable only with fixes at least about 3.6 s apart (tested at 4 s) or a faster pace. Not changed: this is a spec issue for the lead (see the report).
- E-P6 Along window (6.2). `a_prev` is not in `DetState::Armed`. The detector derives it by projecting the newest three fixes in order: the oldest onto the whole route, each later one onto `[a_prev - 100 m, a_prev + 500 m + v_eff x 30 s]` after its predecessor (idle: all three onto the whole route). A window that overlaps no segment falls back to the whole route (E-G5). Consequence: the window protects a track that was on the right leg three fixes ago; it cannot repair a wrong first projection. Adding `a_prev_mm` to `Armed` would make the spec exact; that is a `proxim-types` change (open question).
- E-P7 Arming (6.2). The fix on which the detector arms is not itself a confirming fix: arm, confirm (`confirm_t`), fire needs three consecutive gate-passing fixes (fire at least 1 s after the confirmation). With `D_fire` far inside `d_hi` this is invisible; with `D_fire` near `d_hi` the fire lands two to three steps inside `d_hi`.
- E-P8 Gates (6.2). Order: reach (`OUT_OF_RANGE`, beyond `reach_m`, outside the 150 km frame, armed returns to idle), `FIX_STALE` (age clamped to >= 0), `FIX_ACCURACY_TOO_COARSE`, `OFF_CORRIDOR` (any of the last three fixes), `SPEED_OUT_OF_BAND` (filtered speed; hidden speed fails), `BEARING_MISMATCH` (`dot >= cos` inclusive), `NOT_CLOSING`, `BEYOND_WINDOW`, `PATH_TIER_LOW` (any P1 criterion fails, or `min_path_tier > 1`), `PATH_CONFIDENCE_LOW`. Default reach is `max vertex distance from the origin + max(d_hi, buffer) + 100 m`. The sender speed band is clamped to `[mode minimum, mode default maximum]` (foot 2.5 m/s). The armed hysteresis applies to the band only; the P1 mode minimum (vehicle 2.5 m/s) is not relaxed, so for the default vehicle band the hysteresis has no effect. `d_lo` for foot and cycle is `max(d_lo_m or 100 m, 3 acc_eff)`, always capped at `d_hi`. P1 penalties are exclusive (`-100` above 30 m, `-200` above 50 m, not cumulative), which gives the stated range 400..800.
- E-P9 Latch (6.2). A latched detector rewrites `last_t` on every fix and releases only when the fix is farther than `1.2 x d_hi` (integer ratio 12/10) in a straight line from the anchor point, or cannot be projected. Fixes with `t <= last_t` leave an armed or latched state untouched (`FIX_OUT_OF_ORDER`). A state variant that does not belong to the event kind (for example `cand` handed to an APPROACH signpost) restarts from idle. The late-join drop is `latched{late}` with no event; it is retried only after the release distance.
- E-P10 ENTER (6.1). A fix failing the accuracy gate (`ACC_TOO_COARSE`: circle `acc_mm > 50 m`, or `inradius x 1000 < k_in x acc_eff`) leaves the state byte-identical in every state, including a candidate. A fix that cannot be evaluated (invalid latitude or longitude, or an internal geometry error) counts as `Straddle`; a valid coordinate beyond the 150 km frame counts as `Outside`. Unknown speed counts as slow (10 s dwell). The outside run of `in` restarts after a gap above 120 s; a gap above 900 s becomes `cool{prev_last_t + 30 min}`. The fix that releases a `cool` returns the detector to idle and is not counted toward a candidate. `min_path_tier > 0` or `min_path_conf_milli > 500` on an ENTER signpost can never be met (P0 only): the detector never moves and reports `PATH_TIER_LOW` or `PATH_CONFIDENCE_LOW`. ENTER events carry `dist_to_shape_mm = 0`.
- E-P11 Arithmetic. Time differences and `cool` deadlines saturate (a huge gap or `t` near `i64::MAX` is "very long", which fails closed); all other arithmetic is checked or `i128`. `d_rem_mm` returns 0 for a passed anchor; `t_hat_ms` and `d_rem_mm` reject out-of-contract arguments with `E_PARSE`.

A structurally invalid `State` is `E_PARSE` or `E_LIMIT`: `v != 1`, negative `hwm_ms`, `caps.signposts` or `mem.det` not strictly ascending by id, a trace not strictly ascending in time or above 16 entries, `last_t_ms` older than the newest trace fix, `jump_rejects >= 3`, a heading component above 2^30, more than 4096 caps or detector entries. `clock.now_ms < 0` or `|tz_offset_min| > 840` is `E_PARSE` (UTC-12..+14 fits). More than 4096 signposts, more than 256 zones: `E_LIMIT`. A zone centre with an invalid coordinate is `E_PARSE` and above 80 degrees `E_UNSUPPORTED_LATITUDE` (fail closed: a zone that cannot be evaluated is never skipped). `fix.t_ms < 0` is `FIX_INVALID` (F03 also covers `course_ddeg >= 3600`).
- E-D3 Constants. The [P] numbers of section 7 that `proxim-types::defaults` does not carry (F06 5000 ms, F07 30000 ms, F09 83000 mmps, 100000 mm margin, 60000 ms window, reset at 3, detector prune 900 s, default event age 30 s enter and 10 s approach, default event distance 5000 m, rank 1000, zone ceiling 100 km, tz limit) live in `proxim-decide::params`, as E-P2 did for path and detect. Moving them is a lead decision.
- E-D4 Order. Consent (F01) is evaluated before any argument is looked at beyond structure: a denied call with an invalid fix reports `CONSENT_DENIED`. F09 precedes F10 as written, so a teleport into a standoff reports `FIX_JUMP` (which reveals nothing about the zone) and keeps `mem`. F09 compares raw `acc_mm` (sum of both fixes) plus 100 m, not `acc_eff`; "both accuracies" is read as the sum. A rejected fix (F03 to F09) leaves the state byte-identical except F09's `jump_rejects`; a reset by the third reject clears `mem` and accepts the fix.
- E-D5 High-water mark (7). `caps.hwm_ms` is written only by a call that gets past F10, as the clamped `now`; F01 to F10 leave `caps` byte-identical (spec 11: standoff). Consequence for the lead: `now = max(clock, hwm)` ratchets, so one call with a clock far in the future lifts `hwm` and from then on correctly stamped fixes are `FIX_STALE` or `FIX_OUT_OF_ORDER` until real time passes the mark; the spec offers no recovery. Fail closed, and a spec issue (an OS-authenticated time source in the shell would remove it).
- E-D6 Caps. Day and week counts apply only when the stored index equals the current one (a later stored index, only possible when the timezone moves west, counts as a different bucket and resets, as written); entries from earlier weeks are pruned each accepted call. F22 and F23 compare `>= cap` with the partner cap clamped to 2 and 5; F24 blocks when `now - last_fire_ms < interval`, so a `last_fire_ms` in the future of `now` also blocks. A dropped event (F20 to F24) is consumed (detector keeps its post-event state) and spends nothing; only the slot winner writes `day_n`, `week_n`, `last_fire_ms`.
- E-D7 Revisions. Per id only the highest `rev` is processed. Lower revisions are "superseded" and reported as `TRIGGER_INVALID` drops; two copies of the highest `(id, rev)` are ambiguous and every copy of that id is dropped the same way (nothing is processed, the detector entry is removed). A detector entry whose `rev` differs from the processed one is replaced (idle start). The processing order is the ascending byte order of `(id, rev)`.
- E-D8 Detector pruning. An entry whose id is absent from the input is pruned when `now - last_t > 900 s` (strict); a `cool` entry is instead kept until `now >= until_ms`, because pruning it at 900 s would shorten the 30 minute cool-down of a signpost that left the regional set and came back.
- E-D9 Standoff (F10, F19, I6). The effective standoff of a zone is `clamp(standoff_m or 1000, 1000, 100000)` m: a zone may widen its standoff, never shrink it below the platform default (a smaller value would weaken R1; relaxing is a counsel decision). A zone is evaluated in its own frame; a fix outside the 150 km frame is far unless `standoff + acc_eff` exceeds the frame (unreachable with the 100 km ceiling and 100 m accuracy, kept as a guard). F19 tests only `class=health`: the distance from the zone centre to the circle edge, to the polygon (0 when the centre is inside) or to the nearest route segment is `<= standoff`; vertices beyond a zone's frame are ignored and an edge with one such end is bounded by its near vertex, so a trigger larger than the 150 km zone frame is only partly tested (such triggers are not meaningful). Output without `explain` reads `SUPPRESSED`; with `explain`, `SENSITIVE_STANDOFF`; `decisions` is empty and `notes` absent in both.
- E-D10 Event filters. F20 uses `now - event.t_ms > max_event_age_s x 1000` (`now` is the clamped clock), defaults 30 s enter and 10 s approach; F07 and the detector's 10 s staleness gate make the defaults vacuous for a foreground fix, so they bind through an authored smaller `max_event_age_s` and a lagging clock (golden `aged_clock_event_too_old`). F21 compares `dist_to_shape_mm` (0 for ENTER, cross-track for APPROACH) with `max_event_dist_m x 1000`, default 5000 m.
- E-D11 Output. `Output.t_ms` is the clamped `now`. `path.tier` and `path.conf_milli` are the winning event's, otherwise 0 and 0 (tiers are per signpost; `speed_mmps` and `heading_valid` come from the filters). `notes` is present only with `explain` and only if non-empty; with `explain` every tracked detector adds a `NO_EVENT` note per fix. Terminal reasons (`TOO_LATE_FOR_LEAD`, `UNSUPPORTED_EVENT`, `TRIGGER_INVALID`) are drop decisions; every other detector reason is a note. Drop decisions of static filters carry tier 0, confidence 0, copy `near_you`, `t_ms` = the fix time. Order: fires, then drops, each by `(id, rev, reason id)`.
- E-D12 Policy narrowing. `lead_s_min` clamps to 15..=120, `lead_s_max` to `[lead_s_min, 120]`; the authored `lead_s` must be 15..=120 itself (else `TRIGGER_INVALID`, F12) and is then clamped into the policy range before the detector is prepared. `slots <= 1`, `cap_signpost_day <= 2`, `cap_signpost_week <= 5`, `app_min_interval_s >= 1800`, `max_acc_mm <= 100000`, `sensitivity_ceiling <= 2`. A larger cap or slot count is silently clamped, a smaller one is honoured (0 means never).
- E-D13 Health consent (F15, I12). M1 accepts any non-empty `health_receipt` together with `nearby_health_events=granted`; the receipt is not verified (the SDK issues and checks it, M3). Pack signature, expiry-by-pack and revocation checks (reason ids 500+) are not in `decide`; M1 has only the signpost validity window (F13/F14).
- E-D14 Golden vectors (9). Files are `core/testdata/golden/decide/<id>.json`; `MANIFEST.json` (`{engine_spec, format:"proxim-golden-manifest/1", vectors:[{path, sha256}]}`) lists every JSON file under `golden/` including the two table files, so a silent change of a table is caught. The generator is `cargo run -p proxim-decide --example gen_golden` (dry run, exit 1 on a difference; `PROXIM_BLESS=1` writes). `proxim-sim golden --bless` is not built; the example is the interim tool. `state_sha256` is the SHA-256 of the canonical state text (`caps` and `mem`).
- E-D15 Cost. `decide` prepares every signpost's trigger on every call (projection of all vertices); measured in a release build, 1000 signposts take about 0.9 ms and 4096 about 5.8 ms (`measure` report), fine at 1 Hz; a prepared-trigger cache keyed by `(id, rev)` is the first optimisation when regional sets grow (the API stays pure if the cache is an argument).
- E-D-TZ Caps timezone (7, F22/F23; supersedes the "later index resets" part of E-D6). Found by the conformance suite (S-TZ-CAP-BYPASS): because the day and week buckets were computed from the call's `tz_offset_min`, a caller whose offset changed (DST, travel, or a careless host) moved "today" and got a fresh 2/day. Each `SignpostCaps` entry now records the `tz_offset_min` it was counted under and is judged in that zone: its current day and week are `day_week(now, entry.tz_offset_min)`, so no later offset can move it into a new bucket. A fire keeps the entry's zone while its week is current there; otherwise a new entry starts under the call's zone. Legacy entries without the field are judged under the call's offset. Caps stay client-trusted (PLAN 5.6): a host can still delete its own state; this fixes accidental reopening, not a hostile host.
- E-D-HEALTH Health confidence floor (5.3). Found by the conformance suite (D-HEALTH-FLOOR): the detector defaulted `min_path_conf_milli` to 500 for every class, so a health ENTER (P0, 500) fired. A health signpost's floor now defaults to 700 and is never lowered below it by the sender (`proxim-types::defaults::MIN_CONF_HEALTH`). Consequence, as the spec already says: in M1 a health signpost fires only on APPROACH at P1 with accuracy <= 30 m and the bonus; never on ENTER. The golden `health_with_receipt` now shows `PATH_CONFIDENCE_LOW`.
- E-D-POS No positional structs (3.2). Found by the conformance suite (D-NESTED-POSITIONAL): serde's derived deserializers accept a JSON array as a positional struct at any depth. Every strict decode (`proxim_types::strict::decode_tree`, used by `from_json*` and `decide_json`) now re-encodes the decoded value and rejects the input if any array in it is not an array at the same place in the re-encoding (reserved fields, never re-emitted, are skipped). This reaches fields inside internally tagged enums, which a wrapping deserializer would not.
- E-G11 Table file header (9). Found by the conformance suite (D-TRIG-HEADER): the two table files carried the header fields at top level while decide vectors nest them under `header`. Both table files now use `{"header": {format, kind, id, engine_spec, synthetic}, ...}`. Row data and row digests are unchanged.

### 2026-10-16, category matching (decision implementer)

- E-D-CAT Category matching (new 7.1). Partners can now say which industries they accept (`categories_accepted`) and which they prefer (`category_affinity`), and a block now covers sub-categories. New reason `CATEGORY_NOT_ACCEPTED` (210, appended to the 200 row). The score gains the affinity factor; with no affinity entries it is byte-identical to before, so no golden vector moved. Cross-app routing (which partner apps receive a campaign at all) is a backend decision and is modelled, with its reach and duplicate trade-off, by the phone simulator in `proxim-sim` (`docs/phone-simulator.md`).

### 2026-10-16, health adverts for people on foot (decision implementer)

- E-P-FOOT Strong foot evidence (5.3). The phone simulator showed that no health advert could ever reach a pedestrian: health needs confidence 700 (E-D-HEALTH) and foot P1 was capped at 600. The fix is NOT to let health fire on ENTER at a facility: an advert at or near a health-care facility is what Washington (2,000 ft) and Connecticut and Nevada (1,750 ft) restrict, and PLAN 1 and 6.5 keep every health advert outside a 1,000 m standoff of any facility (F10, F19 with the facility zones the SDK supplies). Instead the foot cap rises to 700 when the walker's evidence is strong: at least 5 fixes in 60 s, heading within 15 degrees of the route, and the worst `acc_eff` of the last 3 fixes at most 20 m (`P1_CONF_FOOT_STRONG_CAP`, `P1_FOOT_STRONG_ACC_MM`). So a walker heading towards a clinic can receive its approach signpost 1 km or more out, but only on good GPS and a steady heading; with a coarse fix (for example 25 m) the cap stays 600 and health never fires. General foot signposts also see 700 under the same evidence (a stronger score, never an extra fire: caps and slots are unchanged). No golden vector moved. Health ENTER still never fires (P0 is 500). [MODEL] until field data (M4): PLAN 5 notes that heading is unreliable below about 2 m/s, so the 15 degree condition will often fail on real walking phones, which only makes the rule stricter. Release of any health traffic is still gated by PLAN 6.5 (counsel sign-off, OHTTP, receipts, registry); the `health_facility` class rules of I7 (no device events, no pacing row) are not yet in the M1 engine, which has only `general` and `health`.

### 2026-10-16, review follow-ups (decision implementer)

- E-D7a Ambiguous ids (E-D7 as written, now implemented). An id whose highest revision appears twice in one call is not processed, and its detector entry is now removed in that call. Before, the entry survived, so a half-confirmed ENTER could fire on its old confirmation when a single copy returned. Test: `proxim-decide/tests/filters.rs::revisions_and_duplicates`.
- E-T1 Canonical depth limit (3.2). `from_canonical_json_with` now checks the canonical form against the caller's `max_depth` rather than the default 32, so a document the plain reader accepts under raised limits is also accepted canonically. The defaults are unchanged.
- E-D-RANK Rank ceiling (7). `rank_milli` above 3000 counts as 3000 in the score. PLAN 5.6 caps the paid value factor at 3x the category floor ("money cannot buy unlimited relevance"); until now only the server enforced it, so a misconfigured backend could have let a high bid crowd out every other advert on the device. The ceiling sits in `proxim-decide::params::RANK_MAX_MILLI`. No golden vector moved (they use 700 to 2000). Test: `proxim-conformance/tests/selection.rs::rank_above_3000_buys_nothing_more`.
- E-PACK Signed packs (M2, `docs/pack-format.md`). `proxim-pack` verifies the key set, revocation list, tile manifest and pack before any signpost reaches `decide`, and reports failures with the five pack codes of row 500 (plus NOT_YET_LIVE for a revision before its `live_at_ms`). `decide` itself is unchanged: it never sees an unverified signpost and never emits a 500 code. The Signpost gains the reserved input field `pack_kind` (accepted and ignored by `decide`, required and checked by the pack layer so signed content cannot move to another pipe). Tests: `proxim-pack/tests/{attacks,fuzz,golden,tamper}.rs`; TypeScript second implementation in `packages/pack`.
- E-ROT Rotation kernel and envelope layout (OI-ROT-1). `proxim-decide::rotation` ports `tools/rotation-ref/refkernel.py` (policy H `select`, commit, dismiss, the ledger and the pending window) and reproduces the frozen `core/testdata/golden/rotation/golden_v2.json` plus `golden_v2_newcount.json`. Window expiry is applied on every call, and commits carry the decision's day (owner decision R-2026-10-17, Addendum 02 5.3). It is not called by `decide` before M3. The M2 pack entry layout changed to the golden_v2 envelope layout (withheld digests, then shipped bodies; pack-format 4.1), and `pack_v1.json` and `compiled_v1.json` were regenerated. Nothing had shipped, so the format version stays 1. Tests: `proxim-decide/tests/rotation_golden.rs`, `proxim-pack/tests/rotation_envelope.rs`.
- E-SPEC2 engine_spec 2 (M3, slice 1, 2026-10-17). The first M3 behaviour change. `ENGINE_SPEC = 2`; the 22 `decide` vectors were re-blessed. A reviewed diff showed all 631 outputs byte-identical; 214 state hashes moved because a fire now also writes a sender day count. The other golden kinds keep `engine_spec: 1` in their headers, which stays valid (9).
- E-D-CAPS Sender and app day caps, and user controls (7.2). Per sender 3 a day and per app 4 a day (raisable to 8) are now enforced on the device, as are dismiss (7 days), hide (permanent) and report (permanent per sender), all from PLAN 5.6 step 5. The controls are persisted with `caps` and lost on reinstall. Tests: `proxim-decide/tests/caps_controls.rs`.
